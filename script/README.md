# script/

Grouped by what a script does. Folders say *what*, file names say *which*.

Every `combat/` and `gather/` loop is generated, and so are the routines `restock/loadout` and `hotkey/regear`:
edit `module/` and `recipe/` at the repo root and run `node util/build-scripts.mjs`. The design is [content/public/scripting/modules.md](../content/public/scripting/modules.md).

```
combat/    hunting loops per template, shared PvP self sustain
hotkey/    one-shot macros bound to a key: weapon swaps, regear, cancel target, bard buffs, moongate
debug/     diagnostics and test scripts: dump-label, target find/state probes, Telekinesis variable test
train/     skill trainers
gather/    lumberjacking, skinning
loot/      what you do with what you picked up: share-loot, claim-loot, recycle, bank-pouch, stock-vendor
restock/   getting ready to go out: loadout
shelf/     Storage Shelf loadouts generated by outlandsbutler.com, one per template
archive/   scripts not in use: no hotkey, no edits, skipped by util/check.sh
```

Combat loops are named after the template (`dexxer-basic`), variants get a suffix (`bard-necro-enhanced`), shared PvP uses `pvp`, and everything else is `verb-noun` (`claim-loot`,
`stock-vendor`). The full rules are in [content/public/scripting/conventions.md](../content/public/scripting/conventions.md).

## Lumberjacking loop

Use [gather/lumberjack-enhanced.razor](gather/lumberjack-enhanced.razor) (v18), built from
`recipe/lumberjack-enhanced-recipe.razor`. Each pass runs recovery, then the automatic Recall, the reagent read,
Smart Harvest, the self buffs, food and lumber packing. Settings, in-game checks and the version history are in
[content/public/loops/lumberjack-enhanced.md](../content/public/loops/lumberjack-enhanced.md).

- Tracking (`escape/tracking`) sets the hunt filter once before the loop, red by default, and reuses a hunt this
  script already confirmed. After changing the filter by hand, turn Hunting off before Play. Every 5 seconds it
  looks whether Hunting is still on and shows `[ track, check ]` while it is off.
- Recall (`escape/recall`) sends one RecallCharge to Home on a Tracking report within 45 steps or on low spare
  weight, and checks the book and the weight every 5 seconds. Once a Recall is due the buffs
  stand down and gathering stops until the script restarts. Only a server refusal gets a notice: sending is not
  arrival. A character without Tracking skips the hunt check.
- Gathering and lumber packing wait on `var__hold_gathering`: a due Recall, a missing book (`require_runebook`),
  or detection on without a hunt.
- Smart Harvest equips the cached Hatchet into an empty left hand, then runs Use item in hand and target self in
  one block. "No harvestable resources nearby" retries in 2 seconds, anything else in 4. The server's 60-second
  delay after travel still applies.
- Every 2 minutes Logs become Boards and Boards go into the loadout loot bag (`pack/lumber`), with a
  2.5-second budget per phase. A bag is asked for at Play when none is set.
- Warmode and any cursor belong to the player: recovery casts, buffs, food and gathering stand down while either
  is up. Potions and bandages still go out.
- To fight a PK, switch to [combat/pvp.razor](combat/pvp.razor) with its own hotkey
  ([the handbook](../content/public/templates/lumberjack-pvp.md#08) part 8).

## Skinning loop

Use [gather/skinning-enhanced.razor](gather/skinning-enhanced.razor) for dungeon melee with Forensic Evaluation skinning.
The template is a Two-Handed Axe dexxer with Magery 80 for recovery and PK readiness.
It is `bard-mace` without the bard parts, plus the Magery self support of `lumberjack-enhanced`:
Smart Heal/Cure and Greater Heal agents, and Reactive Armor and Magic Reflection kept up above the 20 mana GH + Teleport budget.
A cure potion goes first. A light Heal stands in for bandages that cannot run, and `config__use_light_heal = 1` lets it go beside them. Warmode is toggled by hand (Tab) and no block depends on it.
Melee and targeting stay manual (Z then V). An empty left hand re-arms the cached Two-Handed Axe (5187) when no cast is running.
Over max weight, 2000 gold is dropped at your feet per pass. The skinning knife is used from the backpack.
`config__skin_unowned = 1` targets each creature corpse within 2 tiles, grey or not. Its label must read "corpse" without "remains":
carving a player's remains is a criminal act, and one such act turns direct carving off until the next Play.
A corpse that is too far or hit while busy gets one more request. Carving results and criminal acts are profile overheads. `0` uses Smart Harvest on self, which carves grey corpses only.
A criminal action refusal (Sanctuary Dungeon) switches to Smart Harvest for 5 minutes. Handled corpses are ignored.
Skinning waits while an enemy is remembered, so it runs between fights. A carve moves Razor's last target,
and `setlasttarget` cannot restore it in this client. A Z pick made during the knife cursor cancels that cursor.
The sword codex holds Warrior, Defensive while hurt, the Execute finisher and the Chop ability, none of which rely on weapon specials.
The parry codex holds Bulwark for now (Testudo once its ranks catch up) and the Last Stand finisher,
and Warding while poisoned, bleeding or diseased away from melee. Carving results and the Sanctuary refusal are profile overheads.
`pack/leather` moves carried leather into the loadout loot bag every 2 minutes between fights.
It ignores only bag stacks and never clears the list, so carved corpses stay skipped.
Meet a PK with `combat/pvp` (F4).
Design notes and in-game checks are in [content/public/questions/open-items.md](../content/public/questions/open-items.md#11) part 11.

## Returning to the loop

`loot/recycle` runs every hotkey named in the list `list__resume_script` when it finishes or cannot start because a
required container or tool is missing. An unconfirmed item move, unconfirmed recycling or a stuck action queue stops without resuming:
see the [in-game checks](../content/public/questions/open-items.md#13). The farming loops fill the list at Play with their own Razor hotkey name, the one the profile
stores (`Play Script: gather\skinning-enhanced`): `bard-necro-enhanced`, `bard-archer-enhanced`, `tamer-mage-enhanced`, `tamer-archer-enhanced`, `dexxer-basic`,
`skinning-enhanced` and `lumberjack-enhanced`. The archived `bard-mace` and `bard-throwing` register their `Play Script: archive\…` name.
It is a list because a variable reads a word back as 4294967295 (content/public/scripting/razor.md part 3).
It lasts until the client closes, and with nothing registered recycle just ends. `combat/pvp` does not register,
so recycling during a fight returns to the farming loop.

## Loadout and regear

[restock/loadout.razor](restock/loadout.razor) is a routine built from `recipe/loadout-recipe.razor`: edit the modules
and the recipe, then `pnpm build`. Its choices are settings of its blocks, listed by
`node util/build-scripts.mjs --settings recipe/loadout-recipe.razor`.

- `config__use_sewing_kit_and_id_wand` (`restock/tools`) controls both tools together. `1` keeps one Sewing Kit and one
  ID Wand: duplicates go back to the supply box, and missing tools are fetched. `0` skips both. `pack/sorting` still
  arranges tools already in the backpack.
- `config__id_wand_spare` (`restock/tools`): `1` also carries a spare ID Wand once the carried one is down to 40 uses
  or fewer, `0` keeps one.
- `config__carry_magic_instrument` (`restock/instrument`): `1` keeps exactly one magic instrument, `0` leaves
  instruments alone.
- `config__use_runebook_refill` (`restock/runebook`): `0` skips refilling runebooks, and the scroll box is not asked for.
- `config__aspect_hand_row` (`gear/aspect`): the `[aspect` gump row pressed for the held item, `2` spellbook (default),
  `1` weapon, `0` none. Set the weapon and spellbook rows to the same aspect: activating either turns both.

[hotkey/regear.razor](hotkey/regear.razor) (Alt+0), built from `recipe/regear-recipe.razor`, is for after a death:
it heals to full, puts back on the suit loadout recorded, sorts the backpack and turns the aspects back on.
A supply pouch or loot bag that did not come back from the corpse is reported, not asked for.

## Personal values never go into a script

These files are shared. A container serial typed into one is *someone else's* container for
everyone who pulls it. Keep such values in your Razor profile instead:

```
if not varexist global__my_loot_container
    overhead "[ loot chest, pick ]" 255
    setvar global__my_loot_container
endif
```

`setvar` asks for a target once and stores the serial in your profile; the script carries only the
name (this is `loot/claim-loot`). `archive/mining`, `archive/lumberjack` and `loot/bank-pouch` still
hardcode serials and are being converted. `shelf/` scripts are generated with their owner's shelf serial.

## Checking a script

```sh
util/check.sh                       # every script
util/check.sh script/combat/bard-necro-enhanced.razor
```

Razor has no linter and a missing `endif` is the usual way a script silently misbehaves. `check.sh`
reports unbalanced or mismatched `if / while / for` blocks, and prefixed variables used before anything
assigns them, with line numbers. Bash and awk only.

## Debug scripts

Diagnostics live in `debug/`. Stop the combat loop before running a probe or the Telekinesis test.

| Script | Purpose |
|--------|---------|
| [dump-label](debug/dump-label.razor) | Print the exact label returned for a selected item |
| [debug-target-find](debug/debug-target-find.razor) | Compare serial lookup, range filters and optional body scans |
| [debug-target-state](debug/debug-target-state.razor) | Inspect target state, variable comparison and readiness gates |
| [test-telekinesis-var](debug/test-telekinesis-var.razor) | Cast one Telekinesis using a manually stored target serial |
| [probe-last-targets](debug/probe-last-targets.razor) | Show which last target slot (`lasttarget`, `lastharmful`, `lastbeneficial`) a key moved |

After moving a script, rebind any old hotkey to its `debug\...` path. The probe results are recorded in
[the Razor doc](../content/public/scripting/razor.md#03.A).
